# Issues Encountered

| Date | Issue | Resolution / compromise |
|---|---|---|
| 2026-10-19 | Project kicked off. No issues yet. Known risks: <br>(1) Open Library covers looked up by ISBN are rate-limited (about 100 requests per 5 minutes per IP). <br>(2) Hardcover's API limits are documented only by third parties (about 60 requests/min). <br>(3) Cover colors can't be read from canvas when the image comes from another origin (CORS). | Fetch covers by cover ID or OLID and cache them in our own S3. Proxy and cache Hardcover calls through a Lambda. Do color extraction only on covers we've cached. |
| 2026-10-19 | The sandbox blocks the CDNs the prototype loads libraries from, so the page could not be opened as published | Tested in headless Chromium with the same library versions from npm, served in place of the CDN requests. The CDN check itself happens when the user opens the Artifact. |
| 2026-10-19 | Spine author names were cut off ("BR…") and long titles crowded out the author | The author now shows only when the title still fits at a readable size next to it |
| 2026-10-19 | `node --test src/tests/` fails on Node 22 (treats the folder as a module) | Test script uses a glob: `node --test "src/tests/**/*.test.js"` |
| 2026-10-19 | Two UI files declared the same constant name; because they share one script, the whole page failed to start | The build now stops with the names if any top-level name is declared twice (tested in `src/tests/build.test.mjs`) |
| 2026-10-19 | A mirrored SVG arc path was written with a double minus sign and was rejected by the browser | Path numbers are now computed with signs, and the arc direction flips when mirrored |
| 2026-10-19 | The status chip class `reading` collided with the reading-room container's CSS, so a book being read showed a huge empty box on its stats page | Chips now use `st-read`, `st-dnf`, `st-tbr`, `st-reading` |
| 2026-10-19 | Marble veins made with an SVG filter on ~190 facets caused multi-second stalls (about 1-3 fps in the software-rendered test browser) whenever the stand scrolled back into view | Veins are a canvas-drawn bitmap, small rings skip the texture, and facet counts were cut. In the test browser the stall dropped to under 1.5 s. Real iPhone speed is still unchecked. |
| 2026-10-19 | Pick-up and put-back animations were choppy: Framer Motion updated the transform from JavaScript every frame, and picking a book re-rendered the whole stand at the same moment (a 144 ms stall in testing) | Motion moved to the Web Animations API; screens are memoized; the hidden book is a class toggle. Measured stall at pick time dropped to about 2 ms of JavaScript. |
| 2026-10-19 | Fading the 3D book with `opacity` (or `will-change: opacity`) flattened it into a flat card with no spine or edges | Never animate opacity on the 3D book. The stand's own book fades out underneath instead. Noted in styles.css. |
| 2026-10-19 | Putting a book back ended at the wrong position and size, then snapped. The stand book ended 191 px tall against 128 px; the stage also had no perspective because a flat wrapper sat between it and the perspective element | The pose is now solved from measured corners with real perspective. The app also measured the stand book after starting to fade it, and fading flattens a 3D element and shifts it by about 7 px, so it now measures first and hides second. Handoff gap is now 0-1 px. |
| 2026-10-19 | CSS `scale()` does not scale depth, so the projected book was off by about 4% from the model | Poses use `scale3d()` |
| 2026-10-19 | Hairline dark gaps showed between the flutes of the new shaft, because facets that meet at an angle leave sub-pixel seams that show whatever is behind | Facets are drawn 1.2 px wider, and a solid core sits just inside the shaft |
| 2026-10-19 | The photographed column first appeared far to the lower right, and a flat image inside the 3D group would also have hidden the upper part of the book (it sits at depth 0) | The image is placed in scene pixels as a flat child of the scene, drawn before the 3D group |
| 2026-10-19 | The first stand photograph was silently cut off at the window edge (the window was 13 px too narrow), so it was stretched slightly when shown | Photographs now use roomy windows, and the script stops with an error if a photograph would not fit |
| 2026-10-19 | The bookcase frame first appeared stretched for the same reason (window 392 px, frame 422 px) | Same fix; the bookcase is photographed with 60 px of room around it |
| 2026-10-19 | The stand screenshot timed out at 3x in a bigger window in software rendering | Screenshot timeout raised to 3 minutes; windows sized per piece |
| 2026-10-19 | A book in a high slot showed a bright strip under its spine at the start of the pull-out, because real perspective reveals its bottom page edge | Page edges start in shadow and brighten as the book leaves the shelf |
| 2026-10-19 | Bookcase frames sat too far left on the phone. The Artifact page applies `img { max-width: 100% }`, which shrank the 452 px frame picture to the 360 px case width while keeping its -46 px offset (reproduced locally by injecting that rule) | `.case-frame` and `.stand-image` now set `max-width: none; max-height: none`. Photographed placement itself was already symmetric (-46 px each side). |
| 2026-10-19 | Putting a book back: left and centre books kept showing part of their cover (side wall) until they were inside, because real perspective shows the face toward the screen centre and nothing covers it above the shelf | Shelf put-backs clip the flat perspective wrapper (`.stage-clip`) sideways to the spine's projected width, closing fast between 30% and 85% of the motion (driven by the book's own animation clock). Checked with frames at 60/80/90% for left, centre and right books. |
| 2026-10-19 | Putting a book back: it dipped below its shelf board on the way in (nearer the camera, so its bottom edge projected lower: 383 px against a 315 px slot at half way) | The shelf put-back has a middle keyframe (40% through) that puts the book at shelf height with most of its size and turn already done, then it pushes into the slot. Bottom edge at half way is now 327 px; landing is still exact (0 px). |
